# K241 token-flights post-build notes

(a) performance: the layer re-diffs on every placement change (JSON key compare); flights are plain DOM images with the Web Animations API, at most 24 at once. Ledger changes re-render subscribers once per take-off and landing.
(b) implicit state: each flight is `waiting | flying | done` inside the effect closure; the "first render sets the baseline" rule is a ref (`before === null`). A game that mounts the layer after its first view change loses that change's flights.
(c) kit candidates: none beyond this component. Follow-up: the card variant (Imperium `FlightLayer`, 332 lines, hides a card's destination until it lands); its card-specific places and pile logic do not fit the value-token ledger without a second ledger kind.
