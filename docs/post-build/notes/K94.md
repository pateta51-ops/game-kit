# K94 notes
- Pending triggers are one flat queue in `state.timing.pending`: triggers raised while one resolves join it and are ordered with the rest (netrunner opens a nested window instead). A chain stops at `cfg.triggerCap` (default 200). K95's per-resolution checkpoint goes in the `cfg.afterTrigger` hook.
- `PendingTrigger.occurrences` holds the occurrences themselves (not ids as the pattern note says): `takeSettled` drops them from state, and a reaction needs their data.
- The group marker is the task `timing.groupEnd` on the stack; `timing.triggers` inside a group flags it and returns. K95's checkpoint after `timing.do` should do the same check.
- `simultaneously` takes the game's handler table as an argument (the kit's handlers cannot see the game's).
