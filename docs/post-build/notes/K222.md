# K222 post-build notes

(a) Performance: `ctx.ask` now counts enabled options (one pass over the options) and `applyAction` scans the stack for the bound task only when the top task is not bound to the prompt (old-form asks). Negligible.

(b) Implicit state: `RunCtx.base` (stack depth when the running handler started, -1 outside the runner) is set by the runner around each handler; it exists only to tell "the handler pushed its resume task" from "an unrelated task sits on top". The old ask form leaves the resume task unbound (no `prompt` field), so old games keep their state hashes; only `ctx.ask(prompt, resume)` writes `task.prompt`.

(c) Kit candidates: none (all in the kit already).
