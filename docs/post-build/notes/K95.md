# K95 notes
- The spec placed `derive` and `checks` on `GameRules` (types.ts); they live on `TimingConfig.checkpoint` instead, because the kit's handlers only see the timing config. `types.ts` is unchanged.
- A checkpoint runs after every `timing.do`, also between occurrences of one batch; step 1 still collects only settled batches, so a perInstance trigger is never split.
- Cost: `recompute` serialises `derived(s)` (default the whole state) once per pass; a game with a large state should pass `derived`.
- Replay: games without `cfg.checkpoint` hash the same as main (fake timed game, prevention + triggers + effects scenario: 931c3890a65efd7c before and after).
