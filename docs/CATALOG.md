## achievements

The catalogue as data, achievements as pure functions over finished-game summaries, and the small summary written when a game ends. Nothing earned is stored, so a new definition applies to old games. Needs `play-stats`: the summary is a play-stats record and its store is `createPlayStats` (play-stats holds no summary of its own, only the game's fields). No packages; draws nothing (release 1.0: no motion, no sound). Tests: `achievements.test.ts`. K161 (feats inside a game) extends it.

- **Use it when:** The game has unlockable feats computed from finished-game summaries.
- **Not for:** Live in-game goals or scoring; those are rules and stay in the engine.
- **Key exports:** `SUMMARY_VERSION`, `makeSummary`, `validSummary`, `createSummaryStore`, `countGames`, `checklist`, `bestCount`, `evaluate`, `newlyEarned`, `byFamily`, `DEFAULT_HOLD_MS`, `toastFor`, `firstRun`, `toastSettingsWith`, and 19 more
- **Needs:** [`play-stats`](#play-stats)
- **Came from:** marvel-lcg and ArkhamHorror (ideas only, no code copied)
- **Docs:** [README](../components/achievements/README.md)

## art-pipeline

Game-free scripts that get a card game's art from its sources to `public/` with a manifest `tooling-scripts/art-check.ts` verifies. Everything game-specific (ids, URLs, paths, the order of preference) is in JSON config files; each script takes `--config <json>` (paths relative to that file), exits 0 clean, 1 findings, 2 usage or a failed read, and exports `run(args, io)`. Run with plain `node kit/art-pipeline/<script>.ts`.

- **Use it when:** Game-free scripts for a card game's art, driven by the game's config: an index of one chosen image per card (order, overrides, degraded rule), fetch with sha256, sheet cells and crops, PDF pages as faces, a CI cache keyed on input hashes, publish to public with a manifest art-check reads.
- **Not for:** Mapping card ids to files, the sources' URLs and parsing a dossier: those stay in the game and go in as config.
- **Key exports:** Scripts: `art-index`, `art-fetch`, `art-extract`, `art-render-pdf`, `art-ci-cache`, `art-publish`; `lib`: `cellBox`, `decodePng`, `encodePng`, `imageSize`, `codec`
- **Needs:** [`tooling-scripts`](#tooling-scripts)
- **Came from:** earthborne-rangers
- **Docs:** [README](../components/art-pipeline/README.md)

## audio-gen

Sounds, music and voice lines for a game, made with free local models in WSL and finished by rules in code. Python 3 and ffmpeg; no paid service is called anywhere (the paid speech client is `voice`, K66). Model weights and generated audio are never committed. It knows no game: names, paths, tiers and wording are in a config. Not for the browser.

- **Use it when:** Making the game's sounds, music and voice lines offline with free local models (release 1.2 and 1.3 assets).
- **Not for:** Playing sound in the browser (use sound-player and voice).
- **Key exports:** Python package `audiogen` (CLI `audiogen.py`), see its README
- **Needs:** nothing
- **Came from:** 7is
- **Docs:** [README](../components/audio-gen/README.md)

## card-harness

Card tests on real cards. Test code only; the engine imports nothing here but `createProbe`, and card-language imports the pure `strictProblems` from `strict.ts`. Not here: `validateEffect` in card-language checks one effect at run time, `strictProblems` checks a whole grammar in a test.
