audio-gen YuE2 and tools/heavy-queue: a YuE2 run must never take WSL down. On a 16 GB RTX 5080 with WSL capped at 20 GB RAM + 8 GB swap, two runs crashed the WSL VM ("Catastrophic failure, Wsl/Service/E_UNEXPECTED" until wsl --shutdown, killing every runner job): once during the next cue's demucs (offloadAr auto, on), once during a cue's generation (offloadAr false, one cue per process, 3 heavy jobs queued). Suspect host RAM: YuE2 + demucs + the other heavy slot.
- heavy-queue, by addition: `heavy run --mem <GiB>` runs the command in a memory-capped cgroup (`systemd-run --user --scope -p MemoryMax=<n>G -p MemorySwapMax=0`, or the nearest that works in WSL; fail loudly when no cap can be set, never run uncapped), so the kernel kills the job, not the VM. `heavy run --slots <n|all>` holds that many slots, so nothing else runs beside it.
- audio-gen YuE2: each per-cue heavy job takes all slots and a memory cap (new option `memGiB`, default chosen from measured peak with margin and below the WSL total; README says how it was measured). Before loading the model and before each demucs pass, read MemAvailable; under the need, fail the take with a clear message instead of starting. Free what the pipeline can between generation and demucs. A take killed by the cap is a failed take with the cap named in its error, not a crash of the batch.
- Tests: heavy --mem builds the capped command and refuses when no cap is possible; --slots all waits for and holds every slot; YuE2 passes --mem and --slots all; the MemAvailable check fails a take cleanly.
