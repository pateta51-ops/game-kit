`audio-gen` runs every model on CUDA only (its ACE-Step defaults had put the work on the CPU and slowed the runners): `thinking` defaults to false, `offload` and `allowCpu` are ignored and a worker without CUDA exits 3, Kokoro is created on `cuda`, a VAE decode that ACE-Step would move to the CPU fails the item, two CPU threads at most, workers start under `nice -n 19`, and the first generation of a batch prints its GPU use and stops the batch when it took no CUDA memory (`audiogen/gpu.py`). `tools.py status` reports CUDA per venv. Behaviour change for a game: `allowCpu` and `offload` are ignored, and a config that wants the LM must now say `thinking: true`
