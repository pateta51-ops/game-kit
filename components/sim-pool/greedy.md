# Bounded public-view greedy opponent (K424)

Use `greedyBot` when the computer should select one legal action by comparing immediate public outcomes and, when available, one nested choice by the same seat. See the [opponent recipe](../../docs/recipes/ai-opponent.md) for other opponent policies.

## Connect live play and simulation

The complete [public greedy example](fake/public-greedy.ts) uses the production browser entry and engine. Its game lets a computer seat take points, start a two-step route, or choose a hidden draw or a random effect. Run the example through both entrypoints with `npm test -- components/sim-pool/greedy-engine.test.ts`.

- `view(state, seat)` copies the public score, deck size, and deciding prompt. The game supplies legal answers containing only information the seat may know, including their order and payloads. The example uses `legalAnswers(prompt, rng)` over the public prompt.
- `greedyPreview({ rules, content, reconstruct, score, nested, view, answers })` takes a reconstruction of a disposable kernel state or `undefined`. Use public placeholders for hidden fields and RNG, reconstruct the pending task needed to answer the prompt, and keep authoritative objects out of the reconstruction. Its public placeholder data must satisfy any strict invariants the preview reaches. `score(state)` is a public number. `nested(state)` identifies the same action's continuation. `view` and `answers` project public nested choices.
- `greedyBot({ probe, fallback, maxProbes, maxRootAnswers, ties })` returns a `Bot`. `fallback(view, action)` is the game's finite public score on the same scale as its preview. A probe returns `{ kind: 'complete', score }`, `{ kind: 'choice', score, view, answers }`, `{ kind: 'unknown' }`, or `{ kind: 'rejected' }`. A root probe that reaches a reveal, random result or other-seat continuation uses the fallback. Supply a game-owned probe returning `unknown` if rules can consult hidden data without a reveal event or random draw.
- For live play, call `bot.choose(view, answers, rng)` from `sim-pool/browser.ts` and submit the returned action through the game's ordinary engine entrypoint. The example's `playGreedyTurn` calls `applyAction`. In game-store use `botOpponent(bot)` when the store owns that seat. In Node, use `botDriver(bot, view)` and `playOne` or your worker's `SimGame.driver` from `sim-pool/index.ts`. For parity with live play, key `DriverRng` by the same seed, driver name, and prompt ID and preserve draw order across enumeration and choice.

`maxProbes` bounds probe calls (default 256). The bot probes root answers first and scores unprobed roots via the fallback. It evaluates all answers of a nested choice when they fit the remaining probe budget. It keeps the parent score for an empty nested list, an oversized list, any unknown child, or all rejected children. `maxRootAnswers` bounds root scoring, including fallback calls (default 1,000,000). Both limits require positive safe integers. The game must separately bound answer enumeration and the cost of its callbacks. `ties` defaults to `'first'` and supports `'random'` using `DriverRng`. An explicitly rejected root is skipped even when all alternatives are rejected. Empty legal lists, too many root answers, and nonfinite scores are errors.

The example checks strict engine invariants, stale actions, mandatory effects, and hidden and other-seat preview cutoffs. Give your simulator a consistent `reshuffleHidden` and use [the hidden-shuffle check](README.md#hidden-shuffle-check-k274-g06t9) to exercise actual per-world legal answers and decisions. Keep views, enumeration, preview, and callbacks public by construction.
