# card-harness

Card tests on real cards. Test code only; the engine imports nothing here but `createProbe`, and card-language imports the pure `strictProblems` from `strict.ts`. Not here: `validateEffect` in card-language checks one effect at run time, `strictProblems` checks a whole grammar in a test.

## Rules for agents

**What it does:** Test code for card games: a `Scenario` that builds real positions and plays them, a delivery check, an inventory of printed clauses, spec rows, and a strict validator.

**You must:**
1. Use it in tests only; the engine imports nothing from it but `createProbe`.
2. Give `Scenario` a `ScenarioGame` over the game's `GameRules` (`rules`, `content`, `start()`, `put`, `probe`), or a `ScenarioPort` for a game with its own engine; `run()` with tasks needs `push` and `put` needs `put`, or it throws.
3. Build the position with `put`, `set` and `run`, then `answer(...picks)`; an `answer` refused by the engine throws with the open prompt and options printed.
4. Use `{ strict: true }` for scripted runs: `script(...)` queues answers, `check(label, fn)` fails mid-run, and `done()` fails on a leftover answer, an open prompt or equal entries in `effects(state)`.
5. Use `sc.cast('kind')` to narrow the open prompt; it throws naming the kind found.
6. Run `runInventory` from a game script: every piece of the game's language must be cited by a test file or sit in `baseline`; exit 1 when the report is stale, a piece is uncited, or the baseline lists one cited or gone.
7. Import `literalsOf` / `keysOf` / `nodesOf` from `kit/card-harness/literals`; they need `typescript`.
8. Pin a known bug as `it.fails('EXPECTED FAILURE: ...')`, never delete the test.
9. Trace only the content the engine reads to play: walking `.registry` with `Object.values` marks every id looked up.
10. Write each full-resolve card test as `cardCase({ clause, printed, ar }, fn)` from `kit/card-harness/cardCase` (it imports vitest; the index does not): `printed` the clause's text word for word, and `clause`, `printed`, `ar` as string literals, since `runInventory` reads them from the file's text. `title` adds words after the clause id (`poor`, `IX-03 …`).
11. To count only quoted tests, give each clause its `text` and the inventory the `rulings` ids: such a clause is cited only by a `cardCase` whose `printed` equals `text` and whose `ar` is in `rulings`; any other `cardCase` of it fails `<clause>: quote differs`.
12. Give each interaction row as a piece of kind `interaction` (`IX-nn`, its `cards` and `records`); only a test title (an `it` title or a `cardCase` title) cites it, else `interaction IX-nn has no test`. Pass `interacting: interactionNeeds(records, { modifier, lasting, limited })` (every modifier and lasting record, each card with several limited records): an id in no row's `cards` or `records` fails `<id> is in no interaction row`.

13. Build a game's `cards:check` with `cardsCheckMain(process.argv.slice(2), input, console.log, realRecordIo(fs))` (`./cardsCheck` or the index; Node only) and exit with its code. `input`: `faces` (`{ card, text, clauses? }`, the printed text with its ' ¶ ' marks), `catalogue` (docs/cards/catalogue.json), `records` (`{ id, clause, ...restriction keys, why? }`), `open` (content/open-clauses.json, `{ clause, reason }`), `keys` (the grammar's restriction keys), `words` (content/restriction-words.json: `"<key>:<value>"` to printed phrases), `rulings` (AR ids), `arMap` (`{ id, ar, split? }` per pattern), `readings` (`parseReadings` over every docs/cards/readings/*.md), `batch(id)` (its clause ids); optional `lasting`, `durationKey` (`duration`), `whyKey` (`why`), `exceptions` (`{ id, key, ar }`), `shape`, `wording` and `allowShape` (K509, see `patternProblems`), `baseline` (K513: a path, or `--baseline <path>`; a file of allowed problem lines `<part>: <problem>`, `#` comments and blanks ignored; a problem not in it fails, so does a line no longer found ("remove it from <file>"); `--write-baseline` writes today's lines and exits 0; needs a `RecordIo` with `read` and `write`; `NOTE` lines never count; without a baseline the output is unchanged).
14. The four parts are also pure functions, each returning its problem lines: `clauseProblems` (rejoin, sentence or paragraph end, count, orphans both ways, open clauses need a reason), `restrictionProblems` (each restriction has its words in its clause or a `why` naming a ruling; each printed word has its restriction; a `lasting` record has a duration; an exception cites a known ruling and matches something), `patternProblems` (one record shape per pattern unless its AR-map row has `split`; an encoded pattern needs a row that is not `not read`; K509 opt-ins: `wording: true` (key = the clause text with numbers outside `{...}` icon codes as N, so `{d6}` and `{d8}` differ) or `wording: (clause) => key` compares shapes only among clauses with the same key and names the key and the clashing clauses; `allowShape(clauseId, records)` returning a reason leaves that clause out of the comparison, e.g. a line another line on its card changes with "instead"; `patternNotes(input)` lists `<clause> excused: <reason>` and `cardsCheckMain` prints each as a `NOTE` line that does not change the exit code; without them the output is unchanged), `readingProblems` (the last line per encoded clause is `ok` with the hash of its records now (`recordsHash`), or `ambiguous` citing a ruling).
15. Never write docs/cards/readings/<batch>.md by hand: `--record <batch> --pr <n>` takes the PR's last comment holding verdict lines (`<clause> | ok|wrong|ambiguous|render-gap | <note>`), and fails (writing nothing) on a line naming no clause of the batch, a batch clause with no line, or no such comment; it also refuses on the default branch (`main`, `master` or origin's HEAD), with anything staged, or with other changes to the readings file; else it writes the file with a hash per clause, then `git add` and `git commit -- <file>` (that file only) and `push`; a re-run with the same verdicts prints `readings unchanged` and exits 0. A lasting record's duration needs printed words or a ruling even when `durationKey` is not in `keys`; a key holding `undefined` does not change the hash. In tests pass a fake `RecordIo`, never `realRecordIo`.
16. `--list-restrictions <batch> [n]` prints the batch's `n` (10) clauses with the most restriction words: `<clause> <count> [words] <text>`.
17. For `cards:catalogue`, split and group with `splitClauses(text, lead?)` (first at ' ¶ ', then before each match of `lead`, a lookahead), `numberClauses(card, faces, lead?, from = 1)` (`<card>#<n>` across the faces in order), `maskClause(text, names)` and `groupClauses(clauses, names)` (numbers to `N`, names to `NAME`); never retype a clause. Write `docs/cards/catalogue.json` as the `Catalogue` type (`summary.clauses`, `patterns[{ id, clauses[{ id, card, text }] }]`, `oneOffs` of clauses, `interactions[{ id }]`; more keys allowed) and check it with `catalogueProblems`.
18. Build a game's `cards:screen` (K489) as `screenMain(input, console.log)` (`./screen`) and exit with its code. `input`: `faces` (`{ id, text }` the pack's printed text), `zoom` (the zoom's text function, icons left as `{code}`), `icons` (code to label), `clauses` (`{ id, text }`), `prompts` and `opened` (take both from `Delivery.screens` and `Delivery.opened`, filled when the game's `DeliveryGame` gives `clauseOf(prompt)` (the clause that opened it) and `screen(prompt)` (the words shown, or null to leave it unscanned)); optional `syntax` (`['{', '}']`) and `strip`. Run the card tests first and hand their `screens` and `opened` to the script (a file), or the scan sees none. It prints `zoom <face>: differs at word N` (N is 1-based and counts words after `plainWords` from plain-text: NFKC, curly quotes and dashes made plain, `¶` dropped, split on white space; a longer or shorter zoom differs at the first missing word), `icon <code> has no label` (every code in `icons` or used in a printed text), `prompt for <clause>: no amount` (the clause prints a number and the prompt shows none of its numbers) and `<clause> opens a prompt no test scanned`.
19. (K496) A prompt entry in `prompts` may carry `screenOptions` (the option labels shown) and `engineOptions` (the engine prompt's options), with `label` in the input turning an engine option into its label (default `String`); both given, they must match one for one after `plainWords`, else `prompt for <clause>: option "<x>" on screen, not in the engine` or `prompt for <clause>: engine option "<x>" not on screen`. Pass neither and nothing changes. A custom verb's words must go through card-language's `describeEffect`, so `describeCheck` compares them with the printed clause; a handler that prints its own text outside it is not checked.
20. (K497) Feed `cards:screen` from a played game: in e2e or simulation runs call `recordPrompt(file, { clause, shown, screenOptions?, engineOptions? })` per prompt shown and `recordOpened(file, clause)` per opened text (JSON lines appended to `file`; Node only), then `readScreenLogs([files])` gives `{ prompts, opened }` for `screenProblems` / `screenMain`; a recorded prompt with no amount fails like one from `Delivery`. A game that passes `prompts: []` never runs the prompt checks.
21. (K497) Known `<id> is in no interaction row` findings go in a JSON map you read and pass as `interactingPending` (id to the fix that clears it): they print `<id> is in no interaction row (pending: <fix>)` and do not fail; an entry that is no longer a finding fails as `stale pending entry: <id>`.
22. (K497) Read the restriction words from `wordsPathOf(argv)` (`--words <path>`, default `RESTRICTION_WORDS_PATH` = `content/restriction-words.json`); `cardsCheckMain` given `--words <path>` and a `RecordIo` with `read` (`realRecordIo` has it when `fs.readFileSync` is passed) loads that file as `words`, else it exits 1; with no `words` in the input and no flag it loads `RESTRICTION_WORDS_PATH` through `io.read` when the file exists; `--list-restrictions` and `--record` take `--words` too. `recordPrompt` makes the log folder; `readScreenLogs` skips an unparsable line and names it in the returned `warnings`.
23. (K415) Turn the depth gate on by marking clauses `conditional` (true: it has a condition or a cost; the game decides which) or with `depth: true` on the inventory input; without either, coverage counts as before.
24. (K415) With the gate on, a clause counts as covered only by a full-resolve test: an `it`/`test`/`cardCase` whose title names the clause id (not followed by ` poor`) and whose body calls `expect…(`, `assert…(` or `.should` itself, outside strings and comments. A test under `.skip`, `.todo`, `.skipIf` or a skipped `describe` covers nothing.
25. (K415) Give each conditional clause a test titled `<clause id> poor` (a `cardCase` with `title: 'poor'` is one) whose body calls `expectNotOffered` or `expectNotFired` directly; a helper of yours wrapping them does not count. The poor test never covers the full resolve, nor the reverse.
26. (K415) A player choice: `expectNotOffered(sc, id, attempt?)` fails when an enabled option `id` or a prompt naming `id` (a top-level string field) is open now or was at any step of `sc.history`, when taking it is not refused (`attempt`, default `sc.answer(id)` in `withRewind` while a prompt is open; refused = throws or returns false), or when state or events move. A forced effect: `expectNotFired(sc, id, act?, same?)` fails when any event names `id` (after `act`), when a prompt is open, or when `act` changed the state (`same` projects the part that must not move). Set the condition false or the cost unpayable first; never a test that the effect "resolves to nothing".
27. (K415) `runInventory` reports kind `clause` and kind `poor` per clause, and `## Depth by family` (`family` on the clause, default `clauses`: clauses, conditional, full resolve, poor test, baseline); it exits 1 on `clause:<id> has no full-resolve test`, `poor:<id> has no poor test`, and on `<path> › <title>: its body asserts nothing` or `… calls neither expectNotOffered nor expectNotFired` (not counted) unless that clause's key is in the baseline. Adopt family by family: list the other families' `clause:<id>` and `poor:<id>` in `baseline`; an entry now covered fails as stale.

28. (K532) A clause in `cards:screen`'s `clauses` may carry `amounts`: a list of the numbers of its text that are amounts (an empty list: the prompt needs none), or `'counted'` (worked out at run time: the prompt must show some number). Unset, every number of the text counts as before. A listed number must occur in the clause text (`<clause>: amount N is not in its text`); a prompt showing none of the listed amounts, or no number for `'counted'`, still fails `no amount`. Set it only for a condition's number, a stat line's number or a counted amount; never to hide a prompt that drops a printed amount.

**Common mistakes:**
- (K532) Setting `amounts` (or `[]`) on a clause whose prompt drops a printed amount to make `cards:screen` pass: fix the prompt instead.
- Calling `answer` in strict mode with no open prompt: it throws.
- A `{ from: { state, events } }` start: the state is trusted, not validated, unless `validate` is on.
- An inventory piece listed twice: `runInventory` throws `is listed twice`.
- A cited clause only in a comment with `titleOnly: true`: it is not counted as cited.
- A spec row that still passes with its line's records removed: `cardSpecs` fails it.
- A `cardCase` with a literal `clause` but `printed: P.text` (or `ar` not a literal): counts as `quote differs`. One with no literal `clause` (shorthand `{ clause, printed, ar }`) is skipped, so its clause reads `clause:<id> is cited by no test`.
- An `ok` reading goes stale when any key of the clause's records changes (key order does not count): run `--record` again after the judge re-reads.
- `words` keys compare `String(value)`: a boolean restriction is `"optional:true"`; an object value compares as its JSON.
- (K415) A poor test whose body asserts the score is unchanged but calls neither helper: not counted, and the run fails.
- (K415) A full-resolve test that only plays the card (`sc.run(...)`) with no `expect`: not counted; an `expect` inside a string or comment does not count either.
- (K415) `it.each([...])('CL-1 %s', ...)` and other titles that are not a literal right after `it(`: not read, so they cover nothing with the gate on.
- (K415) `expectNotOffered` after the scenario offered the option earlier (then took it) fails: build the poor position from scratch, not after taking the option.
- A game without clause `text`, `rulings`, `interacting` or `interaction` pieces counts as before; the one change it sees is that a `cardCase(` call's title now counts as a test title.

- **Probe** (`createProbe<D>()`): the engine calls `probe.note(d)` (or `note(() => d)`) where it settles a choice without asking. Off in the game.
- **Scenario** (`new Scenario(game)`): the game passes a `ScenarioGame<G, W, D>` over engine-core's `GameRules<G>`: `rules`, `content`, `start()` (the state to build on), `put(s, card, where)` (a new instance, its id) and its `probe`. Then `put`, `set`, `run(...tasks)`, `answer(...picks)`, `options`, `offered`, `events`, `notes`, `observe(read, fn)`. The rules' invariants run on the built position (`{ validate: false }` to skip).
- **Engine port** (K390): a game with its own engine passes a `ScenarioPort<G, W, D>` instead: engine-core's `EnginePort` (`content`, `start()`, `apply(s, answer)` returning the state or an `Error`, `settle(s)`, `prompt(s)` with options as `{ id, enabled, why? }`, `events(s)` the whole log, optional `invariants(s, content)`, `options(s)`, `put(s, card, where)`, `push(s, tasks)` for `run`) plus `probe` and `effects`. `G` is any `PortTypes` (`state`, `prompt`, `event`, `task`, `content`); prompt ids may be strings. Every Scenario method works the same; `run()` with tasks needs `push`.
- **Delivery** (`new Delivery(game)`): the game passes a `DeliveryGame`: `load(state)` into its own session, `dispatch(picks)` through the table's path returning the settings' answers, `prompt()`, `probe`, `silentNote`, `silentAuto`. `silentChoices()` lists viewer decisions nobody was asked.
- **Inventory** (`runInventory(input, out, check, io)`): `input.pieces` is the game's language as data, `{ kind, id, cite?, cards? }` of any kind (ops, dice patterns, formulas); `clauses` the distinct printed clauses by id and card ids (never text); `tests` from `testFiles(root, dirs)`; `baseline` the `kind:id` allowed uncited. A piece is cited by a test file matching a `cite` regex (default: its id as a word) or naming one of its cards (`directOnly` turns that off). Exit 1 when the report is stale (with `check`), a piece is uncited, or the baseline lists one cited or gone.
- **Printed lines** (K83): `lines` `{ id, records }` each owned by a record or in `openLines`; `records` `{ id, verb }` checked against `routes`; all fail `runInventory`. `clauseIds([{ kind, text }])` (K26): `kind-` plus the shortest unique word prefix.
- **literalsOf(file, type, prop?)** (`./literals` or `./literals/index`, needs `typescript`): string literals of a type, or of one property of each union member, to build the piece list from the game's types. K392: `literalsOf(file, type, { keys: true })` or `keysOf(file, type)` gives the sorted property names of an untagged union (`{ gain: number } | { draw: Draw }`); a member with several keys contributes all of them. K397: primitive members (`number | { gain: number }`) are skipped, and `keysOf(file, type, { first: true })` / `literalsOf(file, type, { keys: 'first' })` return only the first declared key of each member.
- **Inventory `titleOnly: true`** (default off): a piece with no `cite` and a clause count as cited only by an id in a test title (`it`/`test`/`describe`), not one in a comment.
- **Scenario `{ from: { state, events } }`**: starts from a built state and its events; the state is trusted, not validated unless `validate` is on.
- **Checks**: `describeCheck(cards, describe, validate?, tokens?)` (generated reading equals the printed text word for word, `[TOKENS]` both ways); `conforms<Same<A, B>>()` (schema type equals engine type, at compile time); `report(name, errors, log)` gives the exit code. `Is<z.infer<typeof S>, T>` is `Same<DR<..>, T>` (`DR` = deep readonly), for readonly game types.
- **parseCsv(text)**: RFC 4180 reader (quotes, doubled quotes, CRLF or LF); rows as header-keyed string records, blank lines dropped.
- **Strict checks** (`new Scenario(game, { strict: true })`): `script([picks], [picks], ...)` answers the prompts that open next; `check(label, fn)` fails mid-run naming label and step; `done()` fails on a leftover scripted answer, an open prompt (strict), or equal entries in the game's optional `effects(state)`. Strict `answer` with no open prompt throws.
- **Ability trace** (`traceAbilities(registry, field = 'effects')`): pass `.registry` (the game's ability or card record, wrapped) as the content; `considered` holds ids looked up, `resolved` ids whose `field` was read to run. `expectResolved(trace, ...ids)` fails a test whose card never ran, saying looked up or never reached; `clear()` between parts.
- Walking the whole registry (`Object.values`, hashing, validation) through `.registry` marks every id looked up, and run if it reads `field`: trace only the content the engine reads to play.

- **K102 helpers**: a refused `answer` prints the open prompt and offered options (`open()`); `noPrompt()`; `changed([[label, read, delta]], fn)` lists every pair off; `literal()` or `scenarioLiteral(state, events)` gives a `{ from }` literal to paste; `withRewind(fn)` runs a branch and restores; `rulingGroups(describe)` gives `errata` and `faq` wrappers.
- **Record renderer** (K78, `renderRecords({ lines, records, templates })`): each printed line `{ id, text, open? }` followed by its records in English, one template per record `kind` (or `verb`); `say` renders nested pieces. A piece with no template prints `[render-gap kind: {json}]`, a field its template never read `[also {...}]`; `note(r)` adds a `note:` line, `kindOf`/`lineOf`/`idOf` read other shapes. Returns `text` for a reading judge (ok / wrong / ambiguous / render-gap per line), `lines` with each reading's `gaps`, and `stray` records naming no line.
- **Spec rows** (K77, `cardSpecs(name, game, rows, { describe, it })`): a row `{ line, name?, layout, act, expect }`; the game's `SpecGame` gives `records`, `play(layout, act, records, lenient)` and `check(result, e)` (a message or undefined). Two tests per row: it holds, and it fails with its line's records removed (`withoutLine`; `lenient` there: skip an answer nobody asks for). `specCoverage({ records, rows, titles?, exempt? })` gives `missing` lines (no row, no test title starting with the id) and `stale` exemptions.
- **Strict validator** (K97, `strictProblems(grammar, def, optOuts?)`): the grammar is data, `{ tag?: 'op', nodes: { kind: { keys, required?, binds?, scopes?, reads?, note? } }, ref?, given? }`; fails non-JSON values, unknown kinds, unknown keys (`wrong-place` when another kind owns the key), missing keys, a variable read before it is bound (`binds`: for later steps; `scopes`: for its children only). Opt-outs are data `{ rule, path?, citation }`; uncited or matching nothing fails. `grammarReference(grammar)` writes the workers' reference from it; `nodesOf(file, type, tag)` (`./literals`) reads kinds and keys from the engine's union, throwing when the anchor is gone.

- **cast** (K124): `sc.cast('kind')` returns the open prompt narrowed to that `kind`, or throws naming the kind found.
- **Round trip** (K114): `roundTripCards(game, [{ card, where, task? }])` puts each card in a minimal state; problems where the state is not plain JSON (`diffPaths`) or play from the JSON copy differs. `[]` passes.

Known bugs are pinned as `it.fails('EXPECTED FAILURE: …')`.
- **Content gate** (K169, `contentGate(input, log)`): the game script passes `packs` (`validate()` issues; warnings fail unless `allowWarnings`), `broken` packs each with the `code` and `severity` it must report, `generated` files compared with `readGenerated` ("stale: run `regenerate`"), and `features` `{ required, used }` (`requireAll` fails on an unused one). Returns `{ failed }`.

- **cards:check** (K488, `cardsCheck.ts`): the four parts, `--list-restrictions`, `--record` and the clause tools above (rules 13-17); `cardsCheck(input)` returns the four problem lists without logging.

## Use it in 10 lines

```ts
import { expectNotFired, Scenario } from '../kit/card-harness/index'
import { DICE_GAME } from '../kit/card-harness/fake/dice' // yours: a ScenarioGame over your GameRules

const sc = new Scenario(DICE_GAME).set((s) => void (s.dice = [2, 2, 5]))
const [twin] = sc.put('hand', 'twin') // a real card of your catalogue, in your hand
sc.run({ kind: 'play', card: twin as string })
console.log(sc.s.score, sc.events.map((e) => e.type)) // assert on state, events, options(), answer(...)
expectNotFired(sc, 'plain#9') // K415: in a `<clause id> poor` test, nothing of that id fired and no prompt is open
```
