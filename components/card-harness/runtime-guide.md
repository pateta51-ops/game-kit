# Runtime card cases from a loaded pack

Keep one game-owned test entrypoint. Run the same content loader, schemas and selected expansions as the game. Stop on an unsuccessful `loadText`, `load` or `mergePacks` before passing the validated card records to `runCardSuite` or `runtimeCardMain`. The suite uses a structural record adapter, so it accepts records returned by content-pack or another game loader.

Supply the selected packs' printed clause IDs independently of the executable records. For standard cases also supply the printed gain, draw count or cost as verified structured expectations. An amount read from the effect being tested would let the same mistake change the assertion. Give every record a clause through `lineOf` (default `line` or `lines`). Set `conditional: true` when the printed clause has an eligibility condition or cost. The suite requires at least one full resolve and one refusal case for that clause. Supply separate cases for independently meaningful conditions.

`familyOf(clause, records)` selects a member of the game's `families` registry. A family supplies a fresh setup layout, a finite sequence of picks, and one or more projected state assertions. Decline shapes it cannot exercise, including compound effects or mismatched record groups. Locate the clause using engine IDs and ordinary prompts. `standardCardCases` covers fixed `gainResource`, fixed `draw`, and a single resource payment followed by a fixed draw. For the paid draw it prepares exact funds and one below the cost, gives the game the minimum deck size, and checks payment plus deck and hand deltas. The poor case requires the option to be absent or disabled. A game whose rule fires automatically can write a `not-fired` case in its own family. Custom families use `delta` or `equals` assertions from the independent rules reading.

Return the real engine rules, content, seed options and setup data from `start`. The suite creates the state and submits the scripted actions through engine-core. It rejects a script with zero or more than 64 answers, engine violations, a capped trigger chain, unused answers or an unexpected leftover prompt. Set `end` when a named routine boundary should remain open. The game must implement `settled(state, end)` using a semantic discriminator such as the pending resume task and expected legal options. A widget kind alone cannot tell a pending effect from the next turn. The game owns its setup and observation callbacks. Keep them deterministic and bounded.

Give the suite the same `createProbe<RuntimeCardNote>()` the game dispatches into. At actual clause entry emit `{ kind: 'clause-begin', id, observation }`. Emit `{ kind: 'clause', id }` at actual effect dispatch and `{ kind: 'clause-end', id, observation }` after all of that clause's costs, effects and follow-ups. Take independent numeric or scalar observation snapshots from the live states at those boundaries. Exclude unrelated work, including other tasks in the same answer. Keep the markers and dispatch notes outside card-language dry runs. A full resolve needs one such ordered sequence and a changed asserted observation within it. Probe lookups, setup notes and unplayed cases earn no credit.

For a refusal, emit `{ kind: 'clause-attempt', id }` on the real offer or execution path. Use a setup without unrelated changes to the checked fields. A passing refusal needs that attempt, no dispatch and matching assertions. A `not-offered` case watches the supplied clause-specific `optionId` in all observed prompts. A passed full resolve of the same clause must take that option on the answer that starts the clause. Cases where the available maps cannot establish that pairing can use an appropriate game-owned no-fire case when that is the printed contract.

Use the suite as a separate gate from handwritten `runInventory`. Its report lists passed cases, missing records, unsupported families, missing cases/evidence, assertion failures and engine errors. `covered` is based on successful runs. A specific reason may exempt an absent record, unsupported family or missing case. Unknown and stale exemptions fail, and failed executions and assertions still fail. Keep output local to the game.

Pass `mutations: { trials, validate }` when using semantic mutation proof. The same derived rows, setup and independent assertions run against schema-valid mutants via `runClauseMutations`. The suite evaluates runtime evidence on the original pack first and propagates mutation failures. A crashed mutant or a trial with malformed or missing observations receives no assertion credit. Each asserted field must provide finite numbers for a delta or a valid scalar for equality in both snapshots. Use explicit null when the absence of a value is itself expected.

The [synthetic consumer](../../tests/fixtures/card-runtime/pack.ts) calls `loadText` and `mergePacks`, takes the selected `pack.records.card`, and passes independently transcribed printed expectations to the suite. Run `node tests/fixtures/card-runtime/pack.ts` to see passing cases and `node tests/fixtures/card-runtime/pack.ts --bad` to see exit 1 on a loader-valid wrong amount. `--invalid` stops at the loader before any cases run. An expansion adds another gain case through the same family without changing the test entrypoint.
