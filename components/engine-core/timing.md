# engine-core: timing (K93, K111, K94, K96, K112, K95, opt-in)
A worked example (damage, a prevention, a trigger) is in [worked-example.md](worked-example.md).

Built to `docs/patterns/timing-vocabulary.md`. Nothing changes for a game that never calls `would`: `state.timing` and `task.batch` stay absent.

- **Wire it.** `handlers: { ...timingHandlers(cfg), ...mine }`. `cfg.happen(ctx, occ)` does the effect from the occurrence's final numbers; `cfg.event(occ)` is emitted when it happened, with `batch` and `occurrence` added. Optional: `before`, `preventions` / `onPrevent`, `replacementsFor` / `applyReplacement`, `chooser` (default `keys.player`, the affected player), `prompt` (turns the kit's options into the game's prompt; `info.why` is `prevent` or `replace`; default K222: the options with `kind` `timing.<why>` and `seat` the chooser).
- **Start a batch.** `would(ctx, [{ kind, keys, amount, unpreventable }], { shared, order })` returns the batch id; each occurrence runs windows `order` (default `before`, `instead`, `prevention`), then `timing.do`. `shared` keys must be equal in every occurrence (`sharedKeys(s, b)` reads them once). `batchGroups(s, b, by)` (K114) reads one batch as several, per `player`, `source` or `target`: `{ key, occurrences }` in first-seen order ("one or more of your units" per player). K299: `keys.other` is the second object of a two-object action (attach card `target` to host `other`, move X to Y, swap): `shared`, `sharedKeys`, `batchGroups` and hashing treat it like `target`, so a once-per-pair limit keys on `target` and `other` instead of packing `card>host` into `target`.
- **Before window.** `cfg.before` may ask (resume task + `ask`), `cancelBatch(ctx, b)` (its tasks, windows and pending occurrences go; `current` cleared), `ignoreBatch` (occurrences marked `ignored`: windows still run, `timing.do` cancels instead of doing) or `insteadOf(ctx, b, ...tasks)` (ignore, and they run just before the first `timing.do`, tagged with `b`). Tasks pushed by any `cfg` hook join the batch (`inBatch`).
- **Prevention window.** Opens when the occurrence has an amount above 0 and `cfg.preventions` exists. Offers whose `Prevention.prevents` is the kind and whose `used` is below `uses` are asked of the affected player with `PASS`; a pick prevents `max` (or all remaining), then `onPrevent(ctx, offer, n)` pays or counts the use. On close `amount = remaining` and `prevented` adds up; all prevented: the occurrence does not happen (`cancelled`). `prevent(ctx, n)` works in the innermost window; outside one, or unpreventable, it is an `EngineBugError`.
- **Replacement loop (K111).** Candidates from `replacementsFor`, minus `occ.applied`, lowest `cls` only; one applies, several: the affected player picks (option ids are `String(r.id)`). `applyReplacement` returns `kept`/`updated` (loop again; change numbers with `changeOccurrence`), or `replaced` (it pushed what happens instead), `prevented` (amount 0) or `skipped`, which cancel the occurrence (its later window tasks and `timing.do` skip it, so `current` still clears). `occ.result` keeps the last code (`kept` when none applied). A one-use effect removes itself in its own apply.
- **Settle.** Happened and cancelled occurrences stay until `takeSettled(ctx)` (K95 will collect triggers there).
- **Triggers (K94).** Push `timing.triggers` where the after-window opens: it collects occurrences of fully settled batches through `cfg.triggersFor` (`TriggerCandidate`: `once` `perItem` gives one `PendingTrigger` per occurrence, `perInstance` one per batch with all its occurrences; sources named by `enteredPlay(ctx, source)` after an occurrence happened do not answer it), then resolves `state.timing.pending` one at a time, re-collecting after each: players in `cfg.turnOrder` (active first); within one player a prompt (`orderPrompt`, option ids `String(t.id)`) only when one is `interactive` and more than one is not `silent`, else `cfg.priority` (default `DEFAULT_PRIORITY`, `{ auto: key }`), then ability key, then id. Before each: `cfg.invalid` gives a reason to drop it (event `cfg.dropped`), else `cfg.resolveTrigger`. The list stays a flat queue: nested triggers join it; `cfg.triggerCap` (default `TRIGGER_CAP` 200 per chain) drops the rest with `cfg.capped`'s event; `cfg.afterTrigger` runs after each trigger and its follow-ups (K95's checkpoint hook). `cancelBatch` drops the batch's pending triggers.
- **Content in trigger hooks (K296).** `triggersFor(s, occ, content)`, `invalid(s, t, content)` and `held(s, t, content)` get the game's content (`ctx.content`) as their last argument, so a trigger table kept in content needs no module variable.
- **The batch in `triggersFor` (K696).** `triggersFor(s, occ, content, batch)`: `batch` is every occurrence that happened in this settle, the ones whose triggers share one order prompt: all batches collected together (each `simultaneously` member's own `would` batch, an occurrence a replacement made instead), by id, the same list for each of them. Cancelled occurrences (and the one a replacement replaced) are not in it; a batch a trigger's effect makes settles later and sees only its own. It is a frozen array of frozen shallow copies (`occ` is passed as before, not frozen). A game marks a trigger `interactive` only when the order of the batch changes the result, else `silent`, so the order prompt opens only when it matters. A game that ignores it behaves as before.
- **Recipe: ask the order only when it matters (K696, `k696.test.ts`).** A value (`hp`) that resets to 1 when it reaches 6 gets two gains settling together (two gains; for more, compare every order). The test runs this block and checks it against this text:
  ```ts
  const end = (v: number, ns: readonly number[]) => ns.reduce((x, n) => (x + n >= 6 ? 1 : x + n), v);
  const recipe: Partial<TimingConfig<Timed>> = {
    triggersFor: (s, _o, _content, batch) => {
      const ns = batch.map((x) => x.amount ?? 0);
      const order = end(s.hp, ns) === end(s.hp, [...ns].reverse()) ? 'silent' : 'interactive';
      return [{ ability: 'gain', source: 'v', player: 'p2', order }];
    },
  };
  ```
  From 4, +2 and +1 asks the order (2 or 1); from 1, +1 and +1 asks nothing (3).
- **Content in `replacementsFor` (K697).** `replacementsFor(s, occ, content)` gets the game's content (`ctx.content`), as `triggersFor` does, so a replacement that card data switches on is offered only where the data says so, not offered everywhere and declined in `applyReplacement`. A game that ignores it is unchanged. Recipe (`k696.test.ts` runs it and checks it against this text; the content holds `cards`, the card data by id):
  ```ts
  const DOUBLE: Replacement = { id: 1, controller: 'p1', cls: 1, label: 'Double' };
  const double: Partial<TimingConfig<Timed>> = {
    replacementsFor: (_s, o, content) => (content?.cards?.[o.keys.source ?? '']?.doubles === true ? [DOUBLE] : []),
    applyReplacement: (ctx, _r, o) => {
      changeOccurrence(ctx, o.id, { amount: (o.amount ?? 0) * 2 });
      return 'updated';
    },
  };
  ```
- **Held triggers (K292).** `cfg.held(s, t)` true keeps a pending trigger in `state.timing.pending`: `timing.triggers` skips it (and the cap leaves it), and the checkpoint's step 5 opens no after-window when only held ones are pending. `TriggerCandidate.timing` (`when` / `after`, from card-language's `When.timing`) is copied onto the `PendingTrigger` for `held` to read. The game pushes `timing.triggers` where it stops holding (effect end, game action end); the triggers released together then order as above (prompt or priority). With `batchEndAfterTriggers`, a batch's effects last until its held triggers have resolved. A game that never pushes `timing.triggers` again leaves held triggers pending, with no error. Example: an effect is [hit, rest]; a "when" response to the damage interrupts it, an "after" one waits for the effect:
  ```ts
  held: (s, t) => t.timing === 'after' && s.stack.some((x) => x.kind === 'effectEnd'),
  chosen: (ctx) => { ctx.then({ kind: 'rest' }, { kind: 'effectEnd' }); would(ctx, [HIT]); },
  effectEnd: (ctx) => ctx.then({ kind: 'timing.triggers' }), // order: when, rest, after
  ```
- **Simultaneously.** `simultaneously(ctx, rules.handlers, tasks)` runs each member's handler on an empty stack (asking is an `EngineBugError`), then puts all follow-ups in front of the rest, member 1's first; a `timing.triggers` among them waits until the whole group has landed, then runs once.
- **Continuous effects (K96, `durations.ts`).** `addEffect(ctx, { kind, source, target?, value, when?, duration, layer?, after? })` returns its id (from `timing.next`; `state.timing.effects` appears only then). `Duration`: `endOfTurn` / `endOfRound` / `endOfPhase` (optional `phase`), `turnBegins` / `nextTurnBegins` of a player, `endOfBatch` (`ifCancelled` `expire`, or `wait`: it waits, counting nothing, until `bindEffect(ctx, id, b)`), `used` (`spendEffect` counts down), `while: 'sourceInPlay'` (`sourceLeft(ctx, source)`), `game`, and (K541) `{ until: 'event', event, instance? }`: until a named event the game defines ("this combat", "until the next reveal"); the game's own code calls `eventOver(ctx, event, instance?)` once when it happens, and every effect waiting on that name ends then, wherever it was added (inside nested batches, triggers or prompts of it), and the ids are returned. Scoping: give the effect `instance` (the combat's id) and fire with it: `eventOver(ctx, 'combatEnd', 'c2')` ends the effects of instance `c2` and those with no `instance`, never those of `c1` (an outer combat), and a fire with no instance ends only effects with no instance. An effect added after the event fired waits for the next fire of it; one added for an instance that already ended never ends (the game must not add it). The name is free text: the game keeps its names in one place, a typo never ends: `waitingOn(s)` (read-only) lists the `{ event, instance? }` the live effects wait on, so a game can check them against its names or its ended instances. `boundary(ctx, { kind: 'turnEnd' | 'roundEnd' | 'phaseEnd' | 'turnBegin', player?, phase? })` marks what it ends (`nextTurnBegins` becomes `turnBegins` at that player's turn start); an `endOfBatch` effect ends after the batch's last `timing.do` and its follow-ups (a `timing.batchEnd` task under them), or at `cancelBatch`; with `cfg.batchEndAfterTriggers` (game rules decide) it lasts through that batch's after-triggers and ends when the `timing.triggers` chain is over. One added for a batch already over or cancelled ends at once (so does one added in a follow-up when the game's first effect came after that batch's last `timing.do`: no `timing.batchEnd` was placed). Ended effects count nothing; `expireEffects(ctx)` removes them (K95 step 2). Read at use: `effectsOf(s, kind?, filter?, cfg)`, `sumEffects`, `anyEffect`, oldest timestamp first; `cfg.conditions` holds the `when` keys (a missing one is an `EngineBugError`), `cfg.blanked(s)` the sources whose effects are skipped.
- **Recipe: count only the batch itself.** An `endOfBatch` effect lasts through its batch's follow-ups, so it also counts during a batch started inside it (a check started by another check's result). For an effect scoped to "this check" only, filter by the occurrence's own batch: `sumEffects(s, 'extra', (e) => 'batch' in e.duration && e.duration.batch === occ.batch)` (K647, E B24). For a scope that is not one batch ("this combat", which holds several batches and prompts), use the K541 kind with the combat as `instance`: `{ until: 'event', event: 'combatEnd', instance: combat }`, read with `sumEffects(s, 'extra', (e) => 'instance' in e.duration && e.duration.instance === combat)`, and call `eventOver(ctx, 'combatEnd', combat)` when it ends (`k541.test.ts`).
- **Layers (K112).** `layered(s, base, { layers, apply, conditions?, blanked? }, filter?)` folds `apply(v, e, s)` over the active effects that have a `layer`, layer by layer in the game's order, by `stamp` within one; an effect waits for every effect of its `after` kinds in that layer (a cycle falls back to stamp order). The stamp is the id for an effect without `when`; `stampActive(ctx, cfg)` gives a conditional one a fresh stamp the first time it holds (K95 runs it before derive). An undeclared layer is an `EngineBugError`.
- **Checkpoint (K95, `checkpoint.ts`).** With `cfg.checkpoint` a `timing.checkpoint` task runs after every `timing.do` and its follow-ups (below its `timing.batchEnd`), after each trigger and `cfg.afterTrigger`'s tasks, once after a `simultaneously` group (none between members), and wherever the game pushes it (end of an effect, of a phase). Steps: 1 `collectTriggers` (settled batches only), 2 `expireEffects`, 3 `stampActive(cfg.checkpoint.effects)` then `recompute`: `derive(ctx)` until `canonicalJson(derived(s))` (default the whole state) stops changing, more than `recomputeCap` (default `RECOMPUTE_CAP` 10) passes is an `EngineBugError` naming the top-level keys still moving; 4 `checks` in rulebook order: a check that returns true, asks or pushes tasks sends the checkpoint back to step 1 after them (bounded by the task cap); the answer to a check's question goes to the restart checkpoint (and is lost) unless the check pushed its answer task before asking; 5 a `timing.triggers` when triggers are pending and none is on the stack. Without `cfg.checkpoint` nothing changes.
