# engine-core: timing (K93, K111, K94, K96, K112, K95, opt-in)

Built to `docs/patterns/timing-vocabulary.md`. Nothing changes for a game that never calls `would`: `state.timing` and `task.batch` stay absent.

- **Wire it.** `handlers: { ...timingHandlers(cfg), ...mine }`. `cfg.happen(ctx, occ)` does the effect from the occurrence's final numbers; `cfg.event(occ)` is emitted when it happened, with `batch` and `occurrence` added. Optional: `before`, `preventions` / `onPrevent`, `replacementsFor` / `applyReplacement`, `chooser` (default `keys.player`, the affected player), `prompt` (turns the kit's options into the game's prompt; `info.why` is `prevent` or `replace`).
- **Start a batch.** `would(ctx, [{ kind, keys, amount, unpreventable }], { shared, order })` returns the batch id; each occurrence runs windows `order` (default `before`, `instead`, `prevention`), then `timing.do`. `shared` keys must be equal in every occurrence (`sharedKeys(s, b)` reads them once).
- **Before window.** `cfg.before` may ask (resume task + `ask`), `cancelBatch(ctx, b)` (its tasks, windows and pending occurrences go; `current` cleared), `ignoreBatch` (occurrences marked `ignored`: windows still run, `timing.do` cancels instead of doing) or `insteadOf(ctx, b, ...tasks)` (ignore, and they run just before the first `timing.do`, tagged with `b`). Tasks pushed by any `cfg` hook join the batch (`inBatch`).
- **Prevention window.** Opens when the occurrence has an amount above 0 and `cfg.preventions` exists. Offers whose `Prevention.prevents` is the kind and whose `used` is below `uses` are asked of the affected player with `PASS`; a pick prevents `max` (or all remaining), then `onPrevent(ctx, offer, n)` pays or counts the use. On close `amount = remaining` and `prevented` adds up; all prevented: the occurrence does not happen (`cancelled`). `prevent(ctx, n)` works in the innermost window; outside one, or unpreventable, it is an `EngineBugError`.
- **Replacement loop (K111).** Candidates from `replacementsFor`, minus `occ.applied`, lowest `cls` only; one applies, several: the affected player picks (option ids are `String(r.id)`). `applyReplacement` returns `kept`/`updated` (loop again; change numbers with `changeOccurrence`), or `replaced` (it pushed what happens instead), `prevented` (amount 0) or `skipped`, which cancel the occurrence (its later window tasks and `timing.do` skip it, so `current` still clears). `occ.result` keeps the last code (`kept` when none applied). A one-use effect removes itself in its own apply.
- **Settle.** Happened and cancelled occurrences stay until `takeSettled(ctx)` (K95 will collect triggers there).
- **Triggers (K94).** Push `timing.triggers` where the after-window opens: it collects occurrences of fully settled batches through `cfg.triggersFor` (`TriggerCandidate`: `once` `perItem` gives one `PendingTrigger` per occurrence, `perInstance` one per batch with all its occurrences; sources named by `enteredPlay(ctx, source)` after an occurrence happened do not answer it), then resolves `state.timing.pending` one at a time, re-collecting after each: players in `cfg.turnOrder` (active first); within one player a prompt (`orderPrompt`, option ids `String(t.id)`) only when one is `interactive` and more than one is not `silent`, else `cfg.priority` (default `DEFAULT_PRIORITY`, `{ auto: key }`), then ability key, then id. Before each: `cfg.invalid` gives a reason to drop it (event `cfg.dropped`), else `cfg.resolveTrigger`. The list stays a flat queue: nested triggers join it; `cfg.triggerCap` (default `TRIGGER_CAP` 200 per chain) drops the rest with `cfg.capped`'s event; `cfg.afterTrigger` runs after each trigger and its follow-ups (K95's checkpoint hook). `cancelBatch` drops the batch's pending triggers.
- **Simultaneously.** `simultaneously(ctx, rules.handlers, tasks)` runs each member's handler on an empty stack (asking is an `EngineBugError`), then puts all follow-ups in front of the rest, member 1's first; a `timing.triggers` among them waits until the whole group has landed, then runs once.
- **Continuous effects (K96, `durations.ts`).** `addEffect(ctx, { kind, source, target?, value, when?, duration, layer?, after? })` returns its id (from `timing.next`; `state.timing.effects` appears only then). `Duration`: `endOfTurn` / `endOfRound` / `endOfPhase` (optional `phase`), `turnBegins` / `nextTurnBegins` of a player, `endOfBatch` (`ifCancelled` `expire`, or `wait`: it waits, counting nothing, until `bindEffect(ctx, id, b)`), `used` (`spendEffect` counts down), `while: 'sourceInPlay'` (`sourceLeft(ctx, source)`), `game`. `boundary(ctx, { kind: 'turnEnd' | 'roundEnd' | 'phaseEnd' | 'turnBegin', player?, phase? })` marks what it ends (`nextTurnBegins` becomes `turnBegins` at that player's turn start); an `endOfBatch` effect ends after the batch's last `timing.do` and its follow-ups (a `timing.batchEnd` task under them), or at `cancelBatch`; with `cfg.batchEndAfterTriggers` (game rules decide) it lasts through that batch's after-triggers and ends when the `timing.triggers` chain is over. One added for a batch already over or cancelled ends at once (so does one added in a follow-up when the game's first effect came after that batch's last `timing.do`: no `timing.batchEnd` was placed). Ended effects count nothing; `expireEffects(ctx)` removes them (K95 step 2). Read at use: `effectsOf(s, kind?, filter?, cfg)`, `sumEffects`, `anyEffect`, oldest timestamp first; `cfg.conditions` holds the `when` keys (a missing one is an `EngineBugError`), `cfg.blanked(s)` the sources whose effects are skipped.
- **Layers (K112).** `layered(s, base, { layers, apply, conditions?, blanked? }, filter?)` folds `apply(v, e, s)` over the active effects that have a `layer`, layer by layer in the game's order, by `stamp` within one; an effect waits for every effect of its `after` kinds in that layer (a cycle falls back to stamp order). The stamp is the id for an effect without `when`; `stampActive(ctx, cfg)` gives a conditional one a fresh stamp the first time it holds (K95 runs it before derive). An undeclared layer is an `EngineBugError`.
- **Checkpoint (K95, `checkpoint.ts`).** With `cfg.checkpoint` a `timing.checkpoint` task runs after every `timing.do` and its follow-ups (below its `timing.batchEnd`), after each trigger and `cfg.afterTrigger`'s tasks, once after a `simultaneously` group (none between members), and wherever the game pushes it (end of an effect, of a phase). Steps: 1 `collectTriggers` (settled batches only), 2 `expireEffects`, 3 `stampActive(cfg.checkpoint.effects)` then `recompute`: `derive(ctx)` until `canonicalJson(derived(s))` (default the whole state) stops changing, more than `recomputeCap` (default `RECOMPUTE_CAP` 10) passes is an `EngineBugError` naming the top-level keys still moving; 4 `checks` in rulebook order: a check that returns true, asks or pushes tasks sends the checkpoint back to step 1 after them (bounded by the task cap); the answer to a check's question goes to the restart checkpoint (and is lost) unless the check pushed its answer task before asking; 5 a `timing.triggers` when triggers are pending and none is on the stack. Without `cfg.checkpoint` nothing changes.
- Tests: `checkpoint.test.ts`; `durations.test.ts`; `timing.test.ts`, `triggers.test.ts`, `replace.test.ts` over `fake/timed.ts` (Shield, Ward, Double, Halve, Armor, Mirror fixtures).
