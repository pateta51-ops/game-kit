# engine-core: barred options, the only option, outcome preview (K88, K89, opt-in)

Source: marvel-champions-digital-game (`legal.ts`, `choices.ts`, `preview.ts`; AGPL-3.0, idea only, written new).

- `KernelOption.reason?` (a code, the game's own, e.g. `condition`, `cannotChoose`, `cannotPay`, `noTarget`) and `missing?` (for a missing target, what was missing, read when the prompt opened so later readers never judge it again), beside `why` (the words). `bar(id, reason, why?, missing?)` builds a barred option; `blocked(prompt)` lists `{ id, reason, why, missing }` for the "why can't I?" view (a barred option without a code reads `barred`). `validateAction` puts the code in its `NOT_LEGAL` error when there is one.
- Barred (`enabled: false`, not legal) differs from `idle` (K91: legal, changes nothing). A shown-but-barred target stays in the options with its reason, never left out.
- `onlyOne(prompt)`: when one option is enabled and one pick is required, `{ taken, options }`, else null. `askOrTake(ctx, prompt)` is `ctx.ask` except that such a prompt is answered at once (the resume task on top of the stack gets the answer) and the notice is returned; the game emits it as its own event (or keeps it for the UI): every printed option, the taken one and each barred one with why. A game that never calls it asks as before. K641 `unseen: true` on an option says the answering player has not seen what it is (a face-down card, an unrevealed option): when it is the only legal answer, `onlyOne` is null and `askOrTake` asks, so the player sees there is one option and nothing hidden is revealed or committed for them; a prompt with no `unseen` option behaves as before (`unseen.diff.test.ts`).
- K287 `alone: true` on an option: it is answered only on its own, whatever `min`/`max` say, and does not count toward them. Pick three actions, or Back: `ctx.ask({ min: 3, max: 3, options: [...actions, { id: 'back', enabled: true, alone: true }] })` takes `['back']` or three actions; `['back', 'a', 'b']` is NOT_LEGAL. `enumerateAnswers` lists `['back']` once; `firstPicks`, `outcomePicks` and `randomPicks` skip it unless the other options cannot reach `min`; `ctx.ask` accepts the prompt when they cannot but an alone option is enabled; `onlyOne` takes the alone option when it is the only answer.
- `preview(game, state, picks, content, { count?, nested? })` answers the open prompt on the real engine and throws the result away. It returns `stop` (`complete`; `choice` when `nested(after)` says the prompt now open belongs to this action; `hiddenInformation`; `rejected` with `error`), the `events` and `numbers` (`count(state)` by name, `{ before, after }`).
- It stops at the first task that emits a revealing event (`reveal: true`) or draws randomness (`state.rng` changed): events and numbers are those of the tasks before it. The check is per task, so a game splits a handler that reads hidden cards before it reveals them, or marks the read with a revealing event. It never answers a nested prompt. Named random overrides (K108) leave `state.rng` alone, so a test can preview a random step.
- `legalTable(prompt, split?)` (K119, idea from Rally the Troops `framework.js`, ISC): the prompt's options as one table `{ verb: { noun: option } }`, barred ones included (`enabled: false`, with their reason), so a board highlights a space or piece by its type and id. `split` turns an option id into `[verb, noun]`; by default at the first `:` (`space:12`); an id without one goes under `option` (a game with a real `option:` verb passes its own `split`, or the two share one row). `legalIn(table, verb, noun)` is the option when legal, else undefined. Not built because already covered: the nested call stack is `state.stack` (tasks carry their scope as fields, `ctx.then` calls, the resume task receives the answer; saved, undone and replayed with the state) and the flow is the typed task list `ctx.then(a, b, c)` capped by `MAX_TASKS_PER_ACTION` (`runner.ts`); `FlowQueue` in `state-machines` caps turn and phase requests.
